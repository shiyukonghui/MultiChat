# 修复回复内容显示两个的问题

## 问题分析

同一个模型的回复内容显示两次，原因是**两条渲染路径重叠**：

### 渲染路径

| 路径 | 数据源 | 组件 | 代码位置 |
|------|--------|------|----------|
| 路径1 | `messages` 数组中的 assistant 消息 | `ChatMessageBubble` | App.tsx:306-310 |
| 路径2 | `modelStatuses[model].content` | `StreamingResponse` | App.tsx:312-319 |

**MODEL_DONE 同时做了两件事**（chatReducer.ts:100-107）：
1. 将完整回复作为 ChatMessage 追加到 `messages` 数组 → 路径1渲染
2. 将完整内容存入 `modelStatuses[model].content` → 路径2渲染

### 修复方案

**方案 A（推荐）**：`MODEL_DONE` 不再把内容追加到 `messages` 数组。仅在首次收到 `chunk` 事件时追加一条空的 assistant 消息，后续 `done` 时只更新 `modelStatuses` 状态，不再追加到 messages。

但这样会丢失已完成的模型回复历史，因为切换模型后历史消息里就没有之前模型的回复了。

**方案 B**：`StreamingResponse` 在 `done` 状态时不再渲染，只负责 `streaming` 状态。内容统一由 `ChatMessageBubble` 从 `messages` 中渲染。

这样分工清晰：
- **streaming 阶段** → `StreamingResponse` 实时展示
- **done 阶段** → 内容已存入 `messages`，由 `ChatMessageBubble` 展示

### 具体改动

| 文件 | 改动 |
|------|------|
| `App.tsx` | `StreamingResponse` 的渲染条件从 `streaming \|\| done` 改为只 `streaming` |

### 流程图

```
chunk 事件 → 追加到 modelStatuses[model].content → StreamingResponse 实时更新
                 ↓
done 事件 → content 写入 messages[assistant] → ChatMessageBubble 渲染
         → modelStatuses[model].status = 'done'
         → StreamingResponse 不渲染（因为 status !== 'streaming'）
```
